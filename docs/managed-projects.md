# Koryx managed projects

## Release and activation

Next.js and its ESLint config are pinned to 16.4.6, incorporating the 16.4.5 security fixes (https://github.com/vercel/next.js/releases/tag/v16.4.5). Existing AI SDK versions are pinned to their previously locked versions to avoid unrelated upgrades.

This release requires both migrations, in order, **before** deploying the app: `supabase/migrations/20261120205620_managed_project_workspace.sql`, then `supabase/migrations/20261120214254_source_sync_and_workspace_audit.sql`. Existing orders default to `buyout`. No existing prices or payment snapshots change. Use the connected Supabase project `aroutopmhmeaqqnrhcaf`; never apply to a similarly named project. The current connector does not have permission to this project. Do not publish the application without applying and verifying the migration.

The SQL uses service-role-only, security-invoker functions. RLS is enabled on every new table; anonymous and authenticated database clients receive no access to telemetry secrets, source or attachment metadata. Application routes authenticate every user, verify project ownership, and then use the existing server service-role client. Founder-only actions use the immutable founder ID, not editable user metadata. The bucket `project-private` must stay private; no browser storage policies or public URLs are created.

Verify grants, own/other-client material downloads, monthly/deposit/full/refunded source entitlement, published and draft isolation, duplicate metrics, revoked keys and an opt-in Stripe subscription in test mode before enabling live enrollment. No live order or charge is needed for QA.

## Monthly pricing

Rates are **Koryx planning rules**, not competitor prices or binding AI quotes. CAD v1: care allowance 79 landing / 129 business website / 199 store / 299 application / 99 integration, plus estimated development scope divided by 12, rounded up to a price ending in 9. The development allocation is a pricing input, not instalments or a promise of code ownership after 12 months. The estimate low/high use the same formula. AI reviews scope through the existing signed estimate flow; the server recomputes the monthly projection. A founder records the final monthly amount and agreed service description; the client separately authorizes it in embedded Stripe Checkout.

Research checked 20 November 2026: https://oakharborwebdesigns.com/ advertises $175/month, 12-month minimum, standard 5-page site; https://www.duda.co/pricing lists builder/platform plans separately from custom development; https://webflow.com/pricing distinguishes site and workspace costs. These are different services and currencies; they are context, not converted CAD benchmarks. Koryx's proposed monthly model has no minimum term, no source transfer, agreed usage/update limits and explicit exclusions for domains, third-party charges and new features. Written scope still requires review. Do not advertise unlimited maintenance, guaranteed uptime or unlimited hosting.

Recurring `managed` plans reuse existing consent, idempotent checkout, signed webhook verification, recurring invoice ledger, receipts, refund reconciliation and cancellation. Unlike future domain renewals, managed service collects the first payment at checkout and repeats monthly. It never pays a buyout balance or unlocks source. End-of-period cancellation can be undone with explicit client consent. An ended monthly subscription can be restarted through a new service row and new Checkout consent; its original subscription and ledger remain intact. Setting the provider cancellation flag is itself idempotent; cancellation/continuation calls deliberately do not reuse an idempotency key across different user decisions. End-of-period cancellation is recorded; cancellation does not automatically delete or stop a deployment. Koryx must fulfil the agreed operations and any end-of-service/export arrangements. Building, infrastructure changes and incident repair are not autonomous AI actions in this release.

## Project activity

In the founder's project editor, open **Service & activity**, create a reporting key, and install the files in `integrations/koryx-telemetry/` into that particular project. Set `KORYX_TELEMETRY_KEY` in its **server** environment. Do not use `NEXT_PUBLIC_`. Never attach the Koryx application's own credentials to client projects.

For Next.js, copy `server.ts` to an appropriate server-only library and `next-relay.ts` to `app/api/koryx-activity/route.ts`, adjusting its local import. Mount `KoryxPageView` in a client layout after the site's analytics consent decision (`enabled` defaults to false). It sends an event on initial page load and client navigation, without transmitting the page URL. Exclude the relay route from request instrumentation to avoid feedback loops. React Strict Mode can run effects twice in development; do production traffic QA separately.

For API/workload metrics, call `reportKoryx({kind:'request',status:response.status,duration_ms:elapsed})` **after** the response using Next `after()`, or the host's supported background completion primitive. Await the report inside that primitive; a detached promise is not durable in serverless functions. The reporter times out after 1.5 seconds and does not break client workloads. It is not installed automatically in unrelated repositories.

`POST https://koryx.ca/api/telemetry` accepts a server bearer key and exactly `{id:UUID,kind:'page_view'|'request',status?:100..599,duration_ms?:0..120000,country?:ISO-alpha2}`. Separate per-project keys are hashed at rest. Rotation revokes the previous key. Reports are deduplicated for 32 days, limited to 10,000 per project per minute and rolled up hourly; retention is 90 days. Existing renewal cron prunes old counters/receipts. The UI displays 7/14/30 days, page views, instrumented requests, 5xx counts, average request duration and last report. The geography panel shows aggregate page views by country, a draggable globe, a smooth globe/map morph, country search and CSV. `koryxCountry(request)` trusts `x-vercel-ip-country` only on Vercel (`VERCEL=1`); the relay ignores browser-provided country fields. Other hosts must supply a trustworthy server-side country resolver or report `ZZ` (unknown). Historic views without a country are included under unknown. Country aggregation happens in SQL, so reports are not truncated by the PostgREST 1,000-row page size. Country centres are approximate, and VPNs/proxies can affect location. The system does not report unique people, revenue or uptime. No IP addresses, visitor IDs, URL paths, query strings, user agents or request bodies are stored.

## Brief materials and source handover

Brief uploads are private, 10 files / 3 MB each / 20 MB per request, with a 100 MB daily uploader limit. File uploads can be retried independently; request creation atomically attaches the chosen files and is idempotent by request ID. Saved drafts retain uploaded file IDs on the same device. Existing orders and additional-work requests use the same material area. Images are recognized by bytes and previewed; other files are downloaded as octet-stream with `nosniff` and sandbox headers.

Source supports manual reviewed handovers and an optional production-connected synchronization. For manual handovers, the Founder uploads a draft folder (source files and binary assets, 300 / 3 MB each / 30 MB total), reviews file content and explicitly publishes it. Secret/build/dependency paths are excluded and common credential formats are rejected. Automated checks cannot prove arbitrary source is secret-free; founder review is required. Client project environment values are never fetched. Automatic synchronization uses separately scoped server credentials, described below. The browser shows folders, file search, versions, line numbers, syntax highlighting, white selection, copy/wrap controls and per-file downloads, with no edit/deploy controls or GitHub branding.

Every **client** source metadata and file request rechecks project ownership and full buyout entitlement against the payment ledger (net of refunds), excluding care payments and cancelled projects. A manually set `orders.paid` flag is insufficient. Legacy paid snapshots must cover the agreed quote with no remaining balance. Drafts are founder-only, published file bytes are immutable, and SHA-256 is verified on download. Monthly service access never qualifies for client source. The Founder can browse every project and its available draft/ready source, including unpaid, monthly and refunded projects. Founder-approved imports run regardless of client payment; ready snapshots remain private storage, with client entitlement independently enforced at every list/file request. Raster image assets can be previewed; other binary assets can be downloaded. ZIP archives and secret/configuration paths are excluded from the published source.


## Automatic Source connection

1. Add `KORYX_SOURCE_GITHUB_TOKEN`, `KORYX_SOURCE_VERCEL_TOKEN`, and a strong `KORYX_SOURCE_WEBHOOK_SECRET` to the Koryx server environment only. GitHub: use a fine-grained, read-only token for **selected client repositories**, Contents and Metadata read. Vercel: use access scoped to the intended team/projects with read access to aliases and deployments. Never use `NEXT_PUBLIC_`, put tokens in the database/UI, or reuse the telemetry key. Existing `CRON_SECRET` protects reconciliation.
2. Register a Vercel webhook at `https://koryx.ca/api/source-sync/webhook` for `deployment.promoted`, `deployment.rollback`, and `deployment.succeeded`. Configure its signing secret to match `KORYX_SOURCE_WEBHOOK_SECRET`. The handler verifies HMAC-SHA1 of the **raw** payload with `x-vercel-signature`, deduplicates event IDs, queues work, and acknowledges promptly. A delayed/rollback event is a signal to re-resolve actual production, not an authoritative commit.
3. Open **any** project as Founder → Source → Automatic sync. Enter repository owner/name, hosting project/team IDs and the production domain. Explicitly approve the exact folders/files for that client. Folder roots end in `/`. Saving verifies both provider identities and the deployment serving the domain. A hosted project cannot be assigned to two clients.
4. The worker resolves the production alias and READY production deployment, verifies numeric repository identity, reads the exact Git SHA, checks regular-file Git blob SHA-1 and stored SHA-256, applies path/credential filters, then re-resolves the production alias before an atomic publish. Preview builds, symlinks, submodules, excluded paths, partial imports and invalid blobs cannot replace the current pointer. Rollbacks reuse the corresponding immutable snapshot. Any policy edit revokes previous automatic URLs for clients and starts a new reviewed policy generation. Published manual handovers remain independently visible.
5. Founder-only configuration authorizes private imports for every project, including monthly/unpaid/refunded projects; payment does not block the administrator’s work. Client list/file requests independently require full buyout entitlement. Monthly plans, partial payments, refunds below the contract amount and cancelled contracts do not qualify for client access. Automatic drafts cannot be manually modified/published. Common secret detection is a safeguard, not proof of absence: approve only handover-safe folders and investigate every blocked import before retrying.
6. New snapshots use the existing private bucket, 300 files, 3 MB/file, 30 MB total. Jobs are durable, one active import/project, with six-minute leases, a five-minute function limit, partial-import resumption and up to five automatic attempts. A blocked import needs review and manual retry or a new deployment. Imports exceeding a complete provider tree/response limit need a smaller repository or a manual handover. No broad repository/root defaults are silently approved.
7. `/api/cron/source-sync` runs every five minutes, checks up to five least-recently-checked connections and imports one due job; capacity therefore grows with the number of projects. Webhooks are the fast path; reconciliation recovers missed events. Monitor failed/blocked jobs in the Source panel and Business statistics. The deployment plan must support the existing frequent cron schedules. Browser default Source checks for a new current release once a minute while visible; explicitly selected historic versions stay selected.

Snapshots are retained as version history; storage consumption grows with releases. Keep the approved scope tight and review storage usage. No client receives repository-provider controls, credentials, environment variables, or deploy/start/stop buttons. Source tokens are not configured by this patch because the current connected account cannot access the actual production database; activation still needs access to that project and secure owner-provided integration credentials.

## Business statistics and workspace audit

The Founder sidebar has a dedicated **Business statistics** page. The project board now links there instead of duplicating four summary figures. Database-wide totals include transaction amounts net of recorded refunds and legacy project payments only when no corresponding project ledger exists. Paid manual domain-renewal receipts are included; matching Stripe receipt/payment identifiers are deduplicated. Buyout outstanding excludes monthly quotes and cancelled contracts. Monthly recurring run rate includes active plans without scheduled cancellation, annual plans divided by 12; it is not cash received or a revenue forecast. The daily chart uses the original payment date restated for current refunds, in UTC. Summary totals are all-time; 7/30/90-day selection changes the chart. CSV exports the displayed daily series. The decorative coloured pulse lines are not financial measurements and are hidden from assistive technology. Refresh is every minute while the tab is visible.

The authenticated workspace forces the black theme for Founder, staff and clients, including private modal dialogs and sidebar, while preserving public-site theme preferences. Syntax preview is limited to 100,000 characters; downloads contain the complete verified file. Raster previews remain same-origin/private. Country map/globe pauses animation offscreen or in a hidden tab; reduced-motion users receive static views. Geographic data and the adapted database are distributed with attribution and licenses under `public/data/`; those public files never contain visitor or project statistics.

`npm run test:managed-projects` covers real PostgreSQL migrations, project file ownership, source payments/refunds, private API boundaries, subscription consent/checkout, automatic imports with mocked providers and the actual SQL queue, checksums, rollback, webhook signatures/deduplication, policy revocation and leases, business totals beyond 1,000 transactions, geographic aggregation and syntax rendering. Local browser QA also exercises real React components → server handlers/actions → in-memory PostgreSQL for buyer briefs and private uploads, black themes, source colour/selection, map/globe controls and Founder panels. It does not prove production provider connectivity or live payment processing.
